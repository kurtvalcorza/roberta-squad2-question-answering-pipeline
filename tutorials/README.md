## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/roberta_question_answering_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 7-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the revision generated from, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/roberta_question_answering_input_manifest.json` with the schema, ceilings, each pair's character counts, the `max_answer_tokens` in force, the verdict and one recorded rejection finding (an out-of-range `max_answer_tokens`); `evaluation_report` (EVAL21) writes `outputs/roberta_question_answering_evaluation_report.json` for the first pair — `exact_match`/`f1` against the authored gold with verdict `sample-sanity` (three pairs are a plumbing check, not an accuracy; the report says so), or `not-measurable` when a BYOD record carries no gold, in which case `needs` names the held-out gold spans a real evaluation requires (EVAL9). Metric ids match the repository helpers (EVAL2).
- The notebook exercises `RoBERTaQuestionAnsweringPipeline` carried verbatim in the notebook rather than reimplementing model loading; model acquisition goes through the package: `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision, `verify_snapshot` re-hashes every entry, and `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`); no cell outside the carried module calls `huggingface_hub` or `transformers`.
- The default sample is synthetic: the card-pass smoke's two-sentence Eiffel Tower passage and three questions authored in code, two answerable with the author's gold spans and one deliberately unanswerable with an empty gold list (the SQuAD 2.0 convention). The smoke observations (`Gustave Eiffel`, `1887 to 1889`, empty) are recorded as one run on one machine, not asserted as expected values; the sanity checks are plumbing checks (span is a literal substring at its offsets, null rule consistent, counts within ceilings).
- Decision rule and score semantics: the upstream `transformers` null-vs-span rule with `handle_impossible_answer=True` is stated as `DECISION_RULE` (softmax over context tokens plus `<s>`, best span by `P_start·P_end` within `max_answer_tokens`, empty answer when `P_start(<s>)·P_end(<s>)` is larger); scores are products of softmax masses, not calibrated probabilities; no no-answer threshold offset is shipped — the caller owns that margin.
- Ceilings `MAX_QUESTION_CHARS` (500), `MAX_CONTEXT_CHARS` (3000), `MAX_QUESTION_TOKENS` (64), `MAX_CONTEXT_TOKENS` (384, rejected not windowed), `MAX_ANSWER_TOKENS` (64), `DEFAULT_MAX_ANSWER_TOKENS` (15) and `DECISION_RULE` are printed before the model runs; generative answering, multi-hop reasoning, retrieval, batching, top-k alternatives and a tuned null threshold are named as out of scope.
- CPU is documented as adequate with the card-measured smoke numbers (4.41 s load + verify, 0.105 s / 0.032 s / 0.032 s per call on an Intel Core Ultra 9 275HX).
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- The pinned snapshot is a 7-file manifest with no `tokenizer.json`: `AutoTokenizer` builds `RobertaTokenizerFast` from `vocab.json` + `merges.txt` (documented in the card, README and `docs/WEIGHTS.md`); the notebook's opening **Snapshot note** says so, and Section 3 stages and digest-verifies those seven files before the tokenizer or the model is constructed.
- Licence: the weights are CC-BY-4.0 and the notebook, README, card and `docs/WEIGHTS.md` carry the attribution to deepset the licence requires; the export records it under `model_attribution`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
