#### Description

`deepset/roberta-base-squad2` is the 125-million-parameter `roberta-base` encoder of Liu et al. (arXiv:1907.11692) with a two-logit span head, fine-tuned by deepset on SQuAD 2.0 for extractive question answering, pinned here to revision `adc3b06f79f797d1c575d5479d6f5efe54a9e3b4`. The architecture, read from the snapshot `config.json`, is a 12-layer bidirectional Transformer encoder (`hidden_size` 768, 12 heads, `intermediate_size` 3072, `max_position_embeddings` 514) over a 50,265-entry byte-level BPE vocabulary (`vocab.json` + `merges.txt`, case preserved). At inference the encoder reads the pair `<s> question </s></s> context </s>` once and emits, for every token, a start logit and an end logit; the answer is the context span whose start and end scores multiply highest, unless the `<s>` position scores higher on both, in which case the model says the context does not answer the question — the SQuAD 2.0 "no answer" case the checkpoint was trained on (pinned README: "trained on question-answer pairs, including unanswerable questions"). No adaptation happens at inference: no training, in-context conditioning or retrieval. What this repository adds is packaging and a bounded adaptation contract: the `RoBERTaQuestionAnsweringPipeline` class in `src/roberta_question_answering_pipeline/pipeline.py`, digest verification of the local snapshot (`verify_snapshot`, `stage_missing_files`), input validation with named ceilings, a NumPy re-implementation of the upstream `transformers` null-vs-span rule (`DECISION_RULE`), a fixed output contract, the SQuAD-style `exact_match`/`f1` helpers plus the `validate_inputs` and `evaluation_report` stage helpers, corpus-level metrics with two non-neural baselines (`metrics.py`: always-null and lexical overlap), a digest-pinned real gold-span corpus (`samples.py`: AdversarialQA dRoBERTa, validated and split by article without leakage), a fit check that drops rather than truncates the records the token ceilings would refuse, supervised fine-tuning of the last *k* encoder blocks and the span head (`adapt`, default 2 of 12) with validation-F1 epoch selection, and a safetensors adapter (`save_artifact` / `from_artifact`) that carries only the trained tensors and is bound to the base weight digest.

#### Intended Use and Limitations

###### Primary Intended Uses

The task is extractive question answering: input one natural-language question and one passage (the "context"), both English `str`; output one contiguous span of the context (with its character offsets and a score) or the empty string meaning "the passage does not contain the answer". Envisioned applications are reading-comprehension over short passages the caller has already retrieved — a paragraph from documentation, a support article, a contract clause — in research prototypes, teaching material about extractive readers, and as the reader stage of a retrieve-then-read system where a separate retriever supplies the passage (the upstream README frames the checkpoint exactly as a Haystack `ExtractiveReader`). The second intended use is bounded domain adaptation: given 8–20,000 `{id, question, context, answers}` records with gold spans from the operator's own documents, `adapt` fine-tunes the last two encoder blocks and the span head (14,177,282 parameters, about 11 % of the model) for a few epochs, selects the epoch by validation F1, and `save_artifact` exports the trained tensors as a 56.7 MB safetensors adapter that `from_artifact` applies on top of the digest-verified base — the recorded run lifts held-out AdversarialQA F1 from 12.38 to 26.49 and the answered rate from 43.5 % to 100 % in about seven minutes of CPU training. In a larger system the pipeline is an inference component that proposes a span and a null score for a human or a downstream rule to act on; it is chosen where a 496 MB float32 checkpoint and the CPU latency measured in §Environment (about 0.03–0.1 s per pair) are acceptable and where the unanswerable case must be explicit rather than forced.

###### Primary Intended Users

The intended users are machine-learning engineers, NLP researchers and application developers integrating an extractive reader into research prototypes, internal tooling, or the DIMER model workbench, and adapting it to a document domain for which they hold a small gold-span dataset. The pipeline assumes its users understand that the model can only copy a span that is literally present in the passage (it never composes, infers across sentences, or answers from world knowledge), that the empty answer is a decision the model makes and not an error, that `score` is a product of two softmax masses and not a calibrated probability, that a passage over 384 BPE tokens is refused and must be chunked by the caller (with the risk that an answer straddles a chunk boundary), that corpus exact-match and F1 measure agreement with gold spans rather than usefulness and are only comparable across runs scored on the same gold with the same normalisation, and that a fine-tuned adapter is only as good as the split discipline behind it — every question on a passage must stay in one split, and questions from one document must be grouped, or the validation score is inflated. It is not designed for hobbyist "ask the model anything" use; without a passage there is nothing to extract.

###### Out-of-scope use cases

1. **Capability boundary:** not a generative or abstractive question answerer — it cannot answer yes/no questions, count, compute, combine facts from two sentences, or answer anything not written verbatim in the context; not a retriever (it reads one passage the caller supplies; pair it with `qwen3-embedding-pipeline` or `qwen3-reranker-pipeline` for retrieval); not multilingual (`language: en` in the pinned README); not a classifier or embedder (for those use `bert-masked-lm-pipeline`). Not a general training framework: `adapt` fine-tunes only whole encoder blocks (1–12 of them, the last *k*) plus the span head, with AdamW, a fixed learning rate, no scheduler, no mixed precision, no gradient accumulation and no early stopping beyond epoch selection; the embeddings and the vocabulary are never modified, so it cannot teach the model a new language, and it trains the null decision only through whatever unanswerable records the operator supplies (position 0, the SQuAD 2.0 convention) — on a corpus with none, such as the default sample, the adapted model stops returning the empty answer.
2. **Input boundary:** only `str` is accepted for both fields (`TypeError` otherwise); empty or whitespace-only text, a question over `MAX_QUESTION_CHARS = 500` characters or `MAX_QUESTION_TOKENS = 64` BPE tokens, or a context over `MAX_CONTEXT_CHARS = 3000` characters or `MAX_CONTEXT_TOKENS = 384` tokens is rejected with `ValueError` — the pipeline refuses rather than truncating or sliding a window; `max_answer_tokens` is capped at `MAX_ANSWER_TOKENS = 64`; one pair per call, no batching. Datasets for `validate_dataset`, `evaluate` and `adapt` are lists of `{id, question, context, answers}` records with `answers` a list of `{text, answer_start}` (empty for unanswerable): fewer than `MIN_RECORDS = 8` or more than `MAX_RECORDS = 20000` records, a duplicate or malformed `id` (pattern `^[A-Za-z0-9_.:-]{1,64}$`), an empty question or context, a field over its character ceiling, a gold `text` not found verbatim at its `answer_start`, or a record that is not a mapping is rejected with `ValueError`; `evaluate` accepts 1–`MAX_EVAL_RECORDS = 2000` records; `adapt` requires at least `MIN_RECORDS` training records, refuses any training record over the token ceilings (use `check_fit` first — nothing is truncated), and refuses `epochs` outside 1..20, `batch_size` outside 1..64, `lr` outside (0, 1e-3] or `trainable_encoder_layers` outside 1..12. `load_artifact` refuses an adapter whose `format`, `base_model` id, revision or `weight_sha256` differ from the constants, whose tensor names are not `roberta.encoder.layer.*` or `qa_outputs.*`, or whose file digest differs from its manifest.
3. **Decision boundary:** not for answers that are acted on without a human checking the span against the passage — medical, legal, financial or safety questions, automated form filling, customer-facing answers published without review — and not for any use where a confidently wrong span or a wrongly suppressed answer causes harm before it is checked. An F1 gain on the operator's validation split is not a release decision: it is a single seeded split of one corpus with no dispersion estimate, and an adapter that answers every adversarial Wikipedia question can have lost the null decision the base model was trained for.

#### Factors

###### Groups

The pipeline is human-adjacent rather than human-centric: it reads and returns natural-language text that routinely mentions people, but it carries no demographic labels and its outputs are spans of the caller's own passage, not decisions about a person. The pinned upstream README reports no group-level breakdown and carries no bias statement at all; the fine-tuning data SQuAD 2.0 consists of Wikipedia paragraphs with crowd-written questions (Rajpurkar et al., 2018), and the `roberta-base` pretraining corpora (BookCorpus, English Wikipedia, CC-News, OpenWebText and Stories, per Liu et al., 2019) were not audited for demographic composition by their authors. Neither the upstream card nor this repository reports how exact-match or F1 vary by the dialect of the question, the domain of the passage, or the named entities involved. The fairness audit therefore transfers to the operator: before deployment, score `exact_match`/`f1` on a labelled sample of your own (question, passage) pairs stratified by the groups that matter to your application — including the rate of wrongly empty answers per group — and treat a systematic gap as a blocker.

###### Instrumentation

There is no physical sensor: the training data was produced by software and people. SQuAD 2.0 was built by crowdworkers on Amazon Mechanical Turk writing questions (and, for SQuAD 2.0, plausible unanswerable questions) against English Wikipedia paragraphs, with answer spans highlighted in the paragraph text (Rajpurkar et al., 2018); the encoder's pretraining text came from web crawls, Wikipedia dumps and book scans. The instrument characteristics that reach the model are text encoding and tokenisation: the byte-level BPE keeps case and punctuation, so casing, Unicode normalisation, HTML residue, hyphenation and line breaks in the caller's passage change the tokens and shift both the span boundaries and the null score; a passage extracted from a PDF with broken words tokenises very differently from the clean Wikipedia prose the model was fine-tuned on. Upstream fine-tuning used `max_seq_len` 386 with `doc_stride` 128 and `max_query_length` 64 (pinned README "Hyperparameters"), which is why this pipeline's ceilings are 64 question and 384 context tokens. The pipeline does not detect encoding damage, boilerplate, or a change in passage domain; it only rejects the type, length and token-count violations listed above.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `torchaudio==2.11.0`, `transformers==4.57.6`, `tokenizers==0.22.2` (exact pins in `pyproject.toml`); `from_pretrained` picks `cuda:0` when available, else CPU, and loads the weights in float32 on both. Measured on this repository's smoke run (Windows venv `dimer-next16`, `CUDA_VISIBLE_DEVICES=-1`, `device="cpu"` passed explicitly, Intel Core Ultra 9 275HX): loading and digest-verifying the 498 MB snapshot took 4.41 s; on a two-sentence Eiffel Tower passage authored in the smoke script (48 context tokens) `Who designed the Eiffel Tower?` (8 question tokens) returned `Gustave Eiffel` with score 0.942 in 0.105 s (first call, includes warm-up), `When was the tower built?` returned `1887 to 1889` with score 0.665 in 0.032 s, and `What colour is the tower painted?` — not answerable from the passage — returned the empty answer with `no_answer_score` 0.876 against a best span score of 0.0001 in 0.032 s. No loader or tokenizer warning was printed; the snapshot has no `tokenizer.json`, so `AutoTokenizer` built `RobertaTokenizerFast` from `vocab.json`/`merges.txt`. Adaptation on the same machine, from the committed notebook's recorded run: reading the pinned 9,018,914-byte AdversarialQA zip from the cache, filtering the dRoBERTa members and cutting 1,000 / 200 / 400 records by article took under a second; the fit check dropped 1 of the 1,600 sample records (a 1,295-character passage of 460 BPE tokens); scoring the frozen model on the 400-question test split took 19–20 s (exact-match 8.0, F1 12.38, answered rate 43.5 %; always-null baseline 0.25 / 0.25 — one test gold span, the initial `A`, normalises to the empty string under the SQuAD rule that strips articles, so the empty prediction matches it; lexical-overlap baseline 0.0 / 8.58); two epochs of AdamW over 999 training questions at batch 16 with the last two encoder blocks and the span head trainable (14,177,282 of 124,056,578 parameters, `lr=3e-5`, weight decay 0.01, gradient clipping 1.0, seed 0) took 410–416 s including the per-epoch validation scoring (validation F1 14.14 frozen → 31.63 → 30.91; epoch 1 selected; answered rate 43.5 % → 100 %); re-scoring the test split took 20 s (exact-match 17.25, F1 26.49, answered rate 100 %); the adapter is 56,713,104 bytes over 34 tensors, and the reloaded pipeline reproduced 8/8 answers byte for byte. Counter-examples recorded during the build on the same split: one epoch of the same configuration reached the same test F1 26.49 in 213 s (epoch 2 did not improve validation F1), and one epoch with only the last block plus the head (7,089,410 parameters) reached F1 24.87 in 194 s — the forward pass through the frozen blocks, not the trainable slice, dominates CPU time. CUDA and the Hub-download path were not executed. Data environment: passages are assumed to be well-formed English prose of the Wikipedia/news/documentation kind with the answer, if any, stated literally in one contiguous span; questions are assumed to be single factoid questions about that passage. Passages far from that distribution (tables, code, transcripts, other languages, heavily formatted text) or questions that require inference yield spans and null scores the pipeline cannot flag as degraded — the upstream README's own numbers fall from F1 82.9 on SQuAD 2.0 dev to 40.4 on adversarial QA (upstream-reported, not measured here).

#### Metrics

###### Performance Measures

Two performance measures, named exactly as the code names them and implemented in `src/roberta_question_answering_pipeline/metrics.py` with the official SQuAD 2.0 normalisation: `exact_match` (1.0 when the normalised prediction — lower-cased, punctuation and the articles a/an/the removed, whitespace collapsed — equals any normalised gold answer, an empty gold list meaning unanswerable) and `f1` (the best token-overlap F1 against any gold answer, 1.0 for an empty prediction against an unanswerable gold and 0.0 for any non-empty prediction there). `exact_match` captures discrete correctness of the whole span and is unforgiving of a boundary off by one word, `f1` gives partial credit for a span that overlaps the gold, and reading only `f1` hides how often the reader returns a slightly wrong span while reading only `exact_match` hides near-misses; both should also be read separately for answerable and unanswerable questions (the upstream README reports `HasAns_f1` 84.03 and `NoAns_f1` 81.80). `qa_metrics(predictions, golds)` averages both over a dataset in percent and adds `answered_rate` (the fraction of questions for which a span was returned) and the count of unanswerable golds; `pipe.evaluate(records)` answers a validated dataset and returns them with the verdict `measured` (≥ `MIN_SCORED_RECORDS = 50` records) or `measured-small-sample`, the elapsed time and the model identity; `null_baseline(records)` scores the empty answer everywhere (exactly the unanswerable fraction) and `lexical_overlap_baseline(records)` scores the passage sentence sharing the most normalised tokens with the question — a bag-of-words reader with no model. F1 selects the epoch in `adapt`. The public per-pair `evaluation_report()` helper is unchanged: `exact_match` and `f1` for one pair with verdict `sample-sanity`, or `not-measurable` with an empty `metrics` list when no gold is supplied. Every result also carries descriptive fields that are not performance measures: `score`, `no_answer_score`, `best_span_score`, `answerable`, `start`, `end` and the two token counts. Upstream reports, on the SQuAD 2.0 dev set with the official script, `"exact": 79.87` and `"f1": 82.91` over 11,873 questions (pinned README "Performance"); this pipeline has not reproduced them. Recorded values on the seeded AdversarialQA dRoBERTa test split (400 questions over 16 articles, `max_answer_tokens` 15): always-null 0.25 / 0.25 (one gold span, the initial `A`, normalises to the empty string because the SQuAD rule strips the articles a/an/the — a quirk of the official normalisation, not an unanswerable question); lexical overlap 0.0 / 8.58; frozen exact-match 8.0 / F1 12.38 with 43.5 % answered; adapted (last two encoder blocks + span head, best of two epochs) 17.25 / 26.49 with 100 % answered; six unseen questions after adaptation with a `measured-small-sample` verdict. The frozen F1 is far below upstream's SQuAD 2.0 dev figure by construction — every dRoBERTa question was kept because a RoBERTa reader failed it — and is not comparable to it.

###### Decision thresholds

The default decision rule is the upstream `transformers` question-answering rule with `handle_impossible_answer=True`, re-implemented in NumPy and exposed as `DECISION_RULE`: the start and end logits are masked to the context tokens plus `<s>` (non-context positions filled with −10000 before the softmax, as upstream does), softmaxed separately, and the best span is the `argmax` over `P_start(i)·P_end(j)` with `i ≤ j < i + max_answer_tokens` — that `argmax` is an implicit threshold and is named as such. The one explicit threshold is the null comparison: `no_answer_score = P_start(<s>)·P_end(<s>)`, and the empty answer is returned whenever it exceeds the best span score. No margin, offset or null-threshold offset is shipped: upstream's official SQuAD 2.0 evaluation tunes a "no-answer threshold" on the dev set, and this pipeline deliberately does not, because that threshold belongs to the deployment's cost of a wrongly empty answer (a missed fact) against a wrongly extracted one (a fabricated fact); the caller who needs it should compare `no_answer_score` against `best_span_score` with their own margin, calibrated on their own labelled pairs. `max_answer_tokens` defaults to `DEFAULT_MAX_ANSWER_TOKENS = 15` (the upstream pipeline's `max_answer_len` default) and caps the span length; raising it towards `MAX_ANSWER_TOKENS = 64` admits longer spans at the cost of over-long extractions. The one selection rule in the adaptation path is explicit: `adapt` keeps the epoch with the highest validation F1 (epoch 0 is the frozen model, so a run that never improves returns the base weights unchanged) and reports `best_epoch` and the per-epoch history; whether the resulting gain on the test split is worth deploying — and whether the lost null decision matters for the deployment — is the operator's decision and no threshold is shipped for it.

###### Approaches to uncertainty and variability

Every reported corpus metric is one value on one seeded split of one corpus: `build_sample_dataset(seed=42)` fixes the 1,000-question draw from the training pool and the article assignment of the dev member into 200 validation / 400 test questions, `adapt(seed=0)` fixes the shuffle order, and no repetition over seeds or splits is performed, so no confidence interval or standard deviation is available and none is claimed — the +14.11 F1 / +9.25 exact-match gain on the test split is a point estimate whose spread is unknown, and the six-question `measured-small-sample` verdict says so explicitly. When gold answers are supplied to the per-pair `evaluation_report`, it computes `exact_match` and `f1` for exactly one pair (`estimation: "single pair"`) and says so — no dispersion exists for one observation, and the verdict is `sample-sanity`, never an accuracy; the upstream dev-set figures are single evaluations by the upstream authors with no reported interval. Inference is deterministic for a given pair, `max_answer_tokens`, weights, device and library versions: there is no sampling, dropout is off under `model.eval()`, and no seed is needed — repeating a smoke call returns the same span and scores, and the reloaded adapter reproduced 8/8 answers. Training is deterministic on one CPU for one seed and library set but is not bit-reproducible across devices or `torch` builds. Float32 kernel differences between CPU and CUDA can move a score in the last digits and, on a near-tie, flip the span or the null decision. The scores are not calibrated probabilities: `score` is the product of two softmax masses that were each normalised over the whole passage, so a long passage spreads mass thin and lowers every score, and the null score is a mass on a single position rather than a probability that the question is unanswerable. A caller who needs a calibrated confidence must fit a calibration map (for example, isotonic regression on `best_span_score` and `no_answer_score`) on their own labelled pairs; nothing in this repository does so.

#### Ethical considerations and biases

###### Data

Upstream discloses that the checkpoint was fine-tuned on SQuAD 2.0 (pinned README "Training data" and the `datasets: squad_v2` front matter), which is English Wikipedia paragraphs with crowd-written questions, and that its base is `FacebookAI/roberta-base`; the pinned README says nothing about the base model's pretraining data, which the RoBERTa paper lists as BookCorpus, English Wikipedia, CC-News, OpenWebText and Stories — web-scale text that was not audited for personal data, so the presence of names, contact details and other personal data of identifiable people is not ruled out and should be assumed. SQuAD 2.0 itself is public and its paragraphs are Wikipedia text about, among other things, living people. This repository distributes code, tests and documentation; the 496 MB `model.safetensors` and the tokenizer files are git-ignored and staged locally under `weights/roberta-base-squad2/` with a manifest. The adaptation sample is not shipped either: `fetch_corpus` downloads one pinned object at run time — AdversarialQA v1.0 from `adversarialqa.github.io` (9,018,914 bytes, SHA-256 `f4f3c232…`), of which only the `3_droberta/train.json` and `3_droberta/dev.json` members are read: 11,000 crowd-written questions over English Wikipedia passages under CC BY-SA 3.0 (Bartolo et al., 2020) — refuses any other bytes, and caches it under `weights/adversarialqa/` (git-ignored). The passages are SQuAD 1.1 Wikipedia paragraphs and name real people, places and events; the sample is used only to fit and score the last two encoder blocks and the span head, and the filtered 1,000 / 200 / 400 subset is reproducible from the digest and `SAMPLE_SEED = 42`. The weights are CC-BY-4.0 and redistributed unmodified with attribution to deepset (see `docs/WEIGHTS.md`); an adapter trained on the sample is a derived work of both and inherits the share-alike attribution obligation of the corpus. Nothing in this corpus is a substitute for the operator's own documents: BYOD records pass through the same validation and are written to `outputs/…_train.csv` in the notebook, so an internal document set with its question log is restricted data the moment it is loaded. The operator must audit the questions and passages they submit or train on for personal, confidential or proprietary content; the pipeline performs no such check and keeps no log.

###### Human Life

The pipeline is not intended for decisions in health, safety, criminal justice, employment, credit, housing or any other domain central to human life, and it has not been validated or certified for any of them by anyone. Its only validation is the offline unit suite (36 tests, plus 2 model-backed tests that run when the snapshot is staged) and the CPU runs recorded in this repository on Wikipedia passages. Where a sensitive use is foreseeable — extracting a dosage from a clinical note, a deadline from a legal notice, an eligibility criterion from a policy document, or fine-tuning on such material — it is admissible only with a human reading the returned span in its passage before it is used, an independent evaluation with gold spans on representative documents that includes unanswerable questions, and whatever regulatory clearance the domain requires; a span this reader returns, or an empty answer it returns, must never be the record of what a document says.

###### Mitigations

Implemented and inspectable in `src/roberta_question_answering_pipeline/pipeline.py`: (1) supply chain — `MODEL_REVISION` is a 40-hex commit; `stage_missing_files` refuses a manifest whose `modelId`/`revision` differ from the constants and fetches absent files only with `allow_download=True`, one file at a time at that revision; `verify_snapshot` re-hashes every file in `weights/roberta-base-squad2/dimer-base-manifest.json` and raises on the first size or SHA-256 mismatch before any weight is loaded; loading is `local_files_only=True` from the verified directory, or from the Hub with `revision=MODEL_REVISION` only when explicitly allowed; `trust_remote_code=False` always; the model libraries are imported only after the snapshot is accepted (`tests/test_import_boundary.py`). (2) Input integrity — `_validate` rejects non-`str`, empty, over-length (`MAX_QUESTION_CHARS`, `MAX_CONTEXT_CHARS`) and over-token (`MAX_QUESTION_TOKENS`, `MAX_CONTEXT_TOKENS`, counted with the real tokenizer) inputs and an out-of-range `max_answer_tokens` before the model runs. The public `validate_inputs()` helper applies the same checks through the same private `_check_inputs()` function and returns an input manifest (schema, ceilings, per-pair observations, verdict, findings), so a caller can record exactly what was accepted or rejected without duplicating the validation logic; the token ceilings stay inside the pipeline because they need the loaded tokenizer. (3) Reproducibility — exact `==` dependency pins, `model.eval()`, float32, deterministic decoding, and `model_id`/`model_revision`/`decision_rule` in every result; `evaluation_report()` records `exact_match`/`f1` for a supplied gold answer as a single-pair `sample-sanity` observation rather than an accuracy. (4) Refusals — no sliding window over long passages (the caller chunks explicitly), no batching, no null-threshold offset; a missing snapshot with `allow_download=False` raises `FileNotFoundError`. (5) Dataset integrity — `fetch_corpus` verifies the byte count and SHA-256 of the pinned zip before it is read and reads its two members with `ZipFile.read` (never `extractall`); `validate_dataset` enforces the record schema, the id pattern, the size bounds, the character ceilings and that every gold span is found verbatim at its offset, and returns a content digest; `check_split_disjoint` fails on any passage shared between splits; `build_sample_dataset` splits the dev member by article and `split_dataset` keeps every question on a passage in one split; `check_fit` drops, and never truncates, the records the token ceilings would refuse. (6) Training and artifact integrity — `adapt` trains only whole encoder blocks and the span head under an explicit `trainable_encoder_layers` bound, refuses any training record over the ceilings, and restores the best-epoch weights so a failed run leaves the base model; `save_artifact` writes a safetensors file of the trained tensors plus a manifest carrying the format tag, the base model id, revision and weight digest, the tensor list and the file SHA-256; `load_artifact` refuses any mismatch in those fields, any tensor outside `roberta.encoder.layer.*` / `qa_outputs.*`, and any digest drift, so an adapter cannot be applied to a different base or altered in transit without failing. No statistical mitigation (re-balancing, output filtering) is applied because the pipeline ships no content filter and adapts to whatever records the operator validates.

###### Risks and harms

Wrong span: the reader returns the highest-scoring contiguous span whether or not it answers the question — a date from the wrong sentence, a name from the wrong clause — and the reader who trusts it bears the harm; likelihood rises with passage length, with questions that need inference, and with passages far from Wikipedia-style prose (upstream F1 drops to 40 on adversarial QA). Wrong null: the empty answer can suppress a fact that is present when the question is phrased differently from the passage, and the operator may conclude the document is silent; likelihood is comparable to the wrong-span case (upstream `NoAns_exact` 81.8 versus `HasAns_exact` 77.9 on the dev set). Boundary loss: a passage over 384 tokens must be chunked by the caller, and an answer straddling a chunk boundary is lost or truncated with no warning. Bias amplification: passages and questions about people inherit the encoder's pretraining biases, and the reader may resolve an ambiguous question to the majority-group entity in the passage; data subjects and third parties bear that harm when the answer is published. Automation bias: a crisp extracted span is checked less carefully than a paragraph. Adaptation drift: an adapter trained on a corpus with no unanswerable questions answers everything — the recorded run's answered rate went from 43.5 % to 100 % — so the null decision the base model was trained for is lost on that corpus and a wrongly extracted span replaces a wrongly empty one; the artifact carries no record of what it was trained on beyond the caller's optional metadata, so a misapplied adapter is a supply-chain risk of the operator's own making — the base-digest binding stops it from loading on the wrong model, not on the wrong domain. Data exposure: submitted text is processed in memory only, but the operator's surrounding system may log it. Magnitude ranges from a wrong lookup to a materially false statement attributed to a document.

###### Use cases

The pipeline must not be used for surveillance, profiling or social scoring — for example answering questions about an individual over scraped personal communications or aggregated records to characterise that person — nor to present an extracted span as a person's own statement or as a faithful record of a document without disclosure. It must not support unlawful discrimination in employment, housing, credit, insurance, education or healthcare access, nor deceptive, manipulative or predatory applications such as auto-answering questions about a product or policy with spans lifted out of context. Any use that violates the CC-BY-4.0 terms of the upstream weights — in particular redistribution without attribution to deepset — or the DIMER deployment terms is prohibited. The developers identify no further prohibited use beyond these because the model's capability is limited to copying one span from one caller-supplied passage.

## Input/output contract

- `RoBERTaQuestionAnsweringPipeline.from_pretrained(device=None, weights_dir=None, allow_download=False)`
- `answer(question, context, *, max_answer_tokens=15)` — `question`: one `str`, non-empty, ≤ 500 chars, ≤ 64 BPE tokens; `context`: one `str`, non-empty, ≤ 3000 chars, ≤ 384 BPE tokens; `max_answer_tokens` 1–64. Returns `{"answer", "score", "start", "end", "no_answer_score", "best_span_score", "answerable", "question_tokens", "context_tokens", "max_answer_tokens", "decision_rule", "device", "source", "model_id", "model_revision"}`; `answer == ""` with `start == end == 0` is the SQuAD 2.0 no-answer.
- `exact_match(prediction, gold_answers)`, `f1(prediction, gold_answers)`, `normalize_answer(text)` — SQuAD scoring helpers (in `metrics.py`, re-exported); an empty `gold_answers` list means unanswerable. `qa_metrics(predictions, golds)` → `{n, exact_match, f1, answered_rate, unanswerable_gold, definitions}` in percent; `null_baseline(records)`, `lexical_overlap_baseline(records)`, `lexical_overlap_answer(question, context)`.
- `validate_inputs(questions, contexts, *, max_answer_tokens=15, names=None)` — input manifest; `evaluation_report(result, gold_answers=None, *, sample_kind="synthetic")` — single-pair evaluation report (`sample-sanity` / `not-measurable`).
- `check_fit(records)` — `{fitting, dropped, n_fitting, n_dropped}` against the token ceilings with the loaded tokenizer; `evaluate(records, *, max_answer_tokens=15)` — validated records (1–2,000) → `{n, exact_match, f1, answered_rate, unanswerable_gold, definitions, max_answer_tokens, verdict, adapted, seconds, model_id, model_revision}`.
- `adapt(train, val, *, epochs=2, lr=3e-5, batch_size=16, trainable_encoder_layers=2, seed=0, progress=None)` — requires `from_pretrained`; `train` 8–20,000 records that fit the ceilings, `val` optional (1–2,000; without it the final epoch is kept); fine-tunes the last *k* encoder blocks plus `qa_outputs` (`k` 1–12; `epochs` 1–20, `batch_size` 1–64, `lr` (0, 1e-3]) with AdamW and keeps the epoch with the highest validation F1; returns `{trainable_encoder_layers, n_trainable, n_total, epochs, best_epoch, selection, lr, batch_size, n_train, n_val, seed, seconds, history, trainable_names}`; sets `pipe.adapter`.
- `save_artifact(directory, metadata=None)` → directory with `adapter.safetensors` (trained tensors only) + `manifest.json` (`format` = `org.valcorza.roberta-base-squad2.adapter.v1`, base `model_id`/`model_revision`/`weight_sha256`, `tensors`, `sha256`); `load_artifact(directory)` verifies, applies the tensors in place and returns the manifest; `RoBERTaQuestionAnsweringPipeline.from_artifact(directory, *, device=None, weights_dir=None)` loads the verified base and applies it.
- `samples.py`: `fetch_corpus(cache_dir=None, fetcher=None)`, `read_corpus(data)`, `flatten_squad(data)`, `filter_records`, `build_sample_dataset(corpus, seed=42, sizes=SAMPLE_SPLIT)`, `fetch_sample_dataset()`, `validate_dataset(records)`, `dataset_digest`, `gold_texts(record)`, `check_split_disjoint(splits)`, `split_dataset(records, val_fraction=0.15, test_fraction=0.2, seed=0)` (by passage), `load_byod_dataset(path)` (JSON array / SQuAD JSON / JSONL / CSV), `write_dataset_csv(records, path)`.
- `verify_snapshot(path=None)` — returns the manifest dict with `path`; raises `FileNotFoundError` / `ValueError`.
- `stage_missing_files(path=None, *, allow_download=False, downloader=None)` — returns the list of manifest entries fetched.
